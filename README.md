# NeuroForge

Android-приложение для Poco X8 Pro Max (Dimensity 9500s): инференс нейросетей на NPU,
диффузионная генерация изображений и апскейл до 4K — полностью на устройстве, без сервера.

---

## Коротко: что здесь честно работает, а что нет

| Заявка | Реальность |
|---|---|
| «Задействует NPU» | Да — через LiteRT NeuroPilot. Но **проверяется замером**, а не декларацией: приложение гоняет один и тот же граф на NPU/GPU/CPU и показывает медианы. |
| «Диффузия на NPU» | **Нет, и это осознанно.** Диффузионный трансформер с int4-весами и динамическим вниманием — не то, что ускоряет APU. Он идёт на CPU/XNNPACK. |
| «Генерация 4K» | Нативно 4K на телефоне не генерирует **никто** — внимание растёт квадратично по числу токенов. Здесь: генерация 512², затем ×4 super-resolution по тайлам → 4096². Вот **это** и есть работа для NPU. |

Главная инженерная мысль проекта: **NPU окупается на апскейлере, а не на генераторе.**
Свёрточная сеть с фиксированной формой входа и int8-весами — ровно то, что APU компилирует
один раз и потом прокручивает 25 раз подряд.

## Железо

| | |
|---|---|
| SoC | MediaTek Dimensity 9500s (3 нм) |
| CPU | 1× Cortex-X925 @ 3.73 ГГц, 3× Cortex-X4 @ 3.3 ГГц, 4× Cortex-A720 @ 2.4 ГГц |
| GPU | Arm Immortalis-G925 MC11 |
| NPU | MediaTek NPU 890 |
| Память | 12 ГБ LPDDR5X, UFS 4.1 |

### Важная оговорка по NPU

Google и MediaTek официально перечисляют поддержку LiteRT NeuroPilot для
MT6878 / MT6897 / MT6983 / MT6985 / MT6989 / MT6991 (последний — Dimensity 9400).
Dimensity 9500s новее этого списка, и его SoC-строка в нём не значится.

Но: в 9500s стоит **NPU 890 — то же поколение, что и в Dimensity 9400 (MT6991)**, который
поддерживается. То есть драйверная база та же, а вот статический allow-list может всё равно
ответить «нет».

Поэтому приложение не гадает. Экран **Device** разделяет три разных утверждения:

1. что за SoC — из `Build.SOC_MODEL`;
2. что говорит статический список LiteRT — `NpuCompatibilityChecker`;
3. **что реально запустилось** — по результатам бенчмарка.

Только третье — доказательство. Первые два регулярно расходятся с реальностью на свежем
кремнии в обе стороны.

## Как получается 4K

```
промпт ──▶ текстовый энкодер ──▶ эмбеддинги
                                     │
seed ──▶ латентный шум ──▶ [ DiT × 4 шага ] ──▶ латент ──▶ VAE ──▶ 512×512
                                                                      │
                                       ┌──────────────────────────────┘
                                       ▼
                       ресэмпл 1024² ──▶ [ ×4 SR, 25 тайлов на NPU ] ──▶ 4096×4096
```

Две стратегии, обе считаются заранее и показываются до запуска:

- **Fast** — один проход сети. 512² → ресэмпл ×2 → 1024² → ×4 → 4096². **25 тайлов.**
- **Quality** — без увеличения ресэмплом: 512² → ×4 → 2048² → ×4 → 8192² → вниз до 4096².
  Резче, но **~5× больше тайлов.**

Пиковая память аккумулятора на 4096² — 256 МиБ; приложение проверяет бюджет кучи **до**
аллокации и отказывается с внятным сообщением, а не падает в OOM внутри пиксельного цикла.

Швы между тайлами растушёвываются: перекрытие 32 px, линейные рампы, нормализация по сумме
весов. Это покрыто тестом, который прогоняет сетку с «сетью-тождеством» и проверяет, что
градиент восстанавливается точно — если это так, любой видимый шов идёт от сети, а не от сшивки.

## Модели

Подробности и рецепты конвертации — [`docs/MODELS.md`](docs/MODELS.md).

| Стадия | Модель | Размер | Куда идёт |
|---|---|---|---|
| Текст | Qwen3-4B (обрезанный), int4 | 1.7 ГиБ | CPU |
| Генератор | **Bonsai Image 4B** — тернарный DiT на архитектуре FLUX.2-klein-4B, int4 block-32 | 2.1 ГиБ | CPU/XNNPACK |
| VAE | декодер, fp32 | 0.2 ГиБ | GPU → CPU |
| Апскейл | **Real-ESRGAN ×4**, int8, тайл 256 px | ~67 МБ | **NPU** → GPU → CPU |

Bonsai Image 4B — на сегодня единственная text-to-image модель с **проверенными** графами
LiteRT: 512×512, 4 шага (step-distilled), пик памяти ~2.9 ГиБ. Три графа грузятся
последовательно и освобождаются между стадиями — иначе в бюджет одного процесса не влезть.
Замеры авторов: ~62 с на iPhone 17 Pro (CPU, XNNPACK, 6 потоков).

Real-ESRGAN публикуется в PyTorch/ONNX, не в LiteRT, — его нужно один раз сконвертировать
и проквантовать на десктопе. Приложение это честно показывает: у такой модели нет кнопки
«Скачать», вместо неё ссылка на рецепт.

## Сборка

```bash
git clone <this repo> && cd -
./gradlew :app:assembleDebug        # нужен Android SDK (compileSdk 36)
```

Чистое ядро собирается и тестируется **без** Android SDK:

```bash
cd core && gradle test              # 65 тестов
```

Для NPU дополнительно нужны рантайм-библиотеки NeuroPilot —
см. [`docs/NPU_RUNTIME.md`](docs/NPU_RUNTIME.md). Без них приложение работает,
просто на GPU/CPU, и прямо об этом пишет на экране Device.

## Структура

```
core/                       Kotlin/JVM, без Android — тестируется на десктопе
  Schedulers.kt             FlowMatch-Euler и Euler-Ancestral
  Noise.kt                  PCG32: воспроизводимый seed
  TileGrid.kt               геометрия тайлинга и растушёвка швов
  RenderPlan.kt             маршрут 512² → 4K, стоимость в тайлах и памяти
  LatentPacking.kt          patchify/unpatchify для DiT
  BpeTokenizer.kt           byte-level BPE
  TensorLayout.kt           CHW ↔ HWC
  ModelCatalog.kt           каталог моделей с пометками о происхождении

app/
  runtime/                  детекция NPU, обёртка CompiledModel, бенчмарк
  models/                   докачиваемая загрузка весов с проверкой
  imaging/                  Bitmap ↔ тензор, тайловый апскейлер
  pipeline/                 оркестровка генерации
  ui/                       Compose: Generate / Device / Models
```

Почему ядро отдельным модулем: планировщики, тайлинг и упаковка латентов — это математика,
где ошибка не падает, а тихо портит картинку. Вынесенные из Android, они покрываются
обычными JUnit-тестами и гоняются за 20 секунд на любой машине.

## Приватность

Веса скачиваются с Hugging Face при первом запуске и остаются на устройстве.
Промпты и изображения никуда не отправляются — сети нет нигде, кроме загрузчика моделей.
