# NeuroForge v1.4.1

Обновления перестают требовать удаления приложения — а значит, перестают стирать скачанные
модели.

---

## «Приложение не установлено, так как оно конфликтует с другим пакетом»

Android отказывается обновлять приложение, если у новой сборки другая подпись. У debug-сборки
здесь своего ключа не было, и AGP в таком случае подписывает автосгенерированным
`~/.android/debug.keystore` — а он создаётся **отдельно на каждой машине**, то есть на каждом
раннере CI был новый.

Следствие: каждая сборка с новой подписью, каждое обновление — конфликт, единственный выход —
удалить приложение. А удаление стирает приватное хранилище, где лежат модели. Несколько
гигабайт, каждый раз.

**Теперь ключ лежит в репозитории** (`app/debug.keystore`), подпись одинаковая на любой
машине, обновления встают поверх установленного.

Это не ослабление: пароль debug-ключа — общеизвестное `android`, сертификат ничего не
удостоверяет. Единственное, что меняется, — подпись перестаёт быть случайной. Релизный ключ
к этому отношения не имеет и остаётся в `KEYSTORE_BASE64`.

## Этот переход — последний с удалением

Установленная у вас версия подписана старым случайным ключом; совместить их нельзя. Но
модели можно сохранить: debug-сборка помечена `debuggable`, значит работает `run-as`, и root
не нужен.

```bash
adb shell run-as dev.neuroforge tar -c -f - files/models > neuroforge-models.tar
adb uninstall dev.neuroforge
adb install app-debug.apk
# запустить приложение один раз и закрыть
adb push neuroforge-models.tar /data/local/tmp/
adb shell run-as dev.neuroforge sh -c 'tar -x -f /data/local/tmp/neuroforge-models.tar'
```

Подробно, включая что делать без компьютера, — [`docs/UPDATING.md`](docs/UPDATING.md).

## Почему модели просто не лежат в месте, которое переживает удаление

Нативным рантаймам нужен настоящий путь в файловой системе: LiteRT-LM отдаёт путь в нативный
код, llama.cpp открывает файл через `fopen`. Storage Access Framework, который удаление
переживает, выдаёт `content://`, а не путь — пришлось бы копировать обратно во внутреннее
хранилище и держать две копии гигабайтных весов. `Android/data` удаление тоже стирает, и с
Android 11 он не виден файловым менеджерам.

Поэтому правильное решение — не переносить модели, а не удалять приложение.
