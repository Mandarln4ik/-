# Обновление без потери моделей

## Почему «Приложение не установлено, так как оно конфликтует с другим пакетом»

Android отказывается обновлять приложение, если у новой сборки **другая подпись**. Это не
защита от вас, это защита от подмены приложения чужим.

До версии 1.4.1 у debug-сборки не было своего ключа. AGP в таком случае подписывает
автосгенерированным `~/.android/debug.keystore`, а он создаётся **отдельно на каждой
машине** — то есть на каждом раннере CI он был новый. Отсюда: каждая сборка с новой
подписью, каждое обновление — конфликт, и единственный выход — удалить приложение. А
удаление стирает его хранилище, где лежат скачанные модели. Несколько гигабайт, каждый раз.

**Начиная с 1.4.1 ключ лежит в репозитории** (`app/debug.keystore`), подпись одинаковая на
любой машине, и обновления встают поверх. Это безопасно: пароль debug-ключа — общеизвестное
`android`, сертификат ничего не удостоверяет; фиксируется только то, что подпись перестаёт
быть случайной.

**Но переход на 1.4.1 — последний, который потребует удаления.** Установленная у вас версия
подписана старым случайным ключом, и совместить их нельзя. Ниже — как сохранить модели.

## Как сохранить модели при этом последнем переходе

Модели лежат в приватном хранилище приложения (`/data/data/dev.neuroforge/files/models`).
Root не нужен: debug-сборка помечена `debuggable`, а значит работает `run-as`.

Нужен компьютер с `adb` и включённая отладка по USB.

**1. Выгрузить модели с телефона**

```bash
adb shell run-as dev.neuroforge tar -c -f - files/models > neuroforge-models.tar
ls -lh neuroforge-models.tar        # должен быть размером со скачанное
```

**2. Удалить старую версию и поставить новую**

```bash
adb uninstall dev.neuroforge
adb install app-debug.apk
```

**3. Запустить приложение один раз** — чтобы оно создало свои каталоги, — и закрыть.

**4. Вернуть модели**

```bash
adb push neuroforge-models.tar /data/local/tmp/
adb shell run-as dev.neuroforge sh -c 'tar -x -f /data/local/tmp/neuroforge-models.tar'
adb shell rm /data/local/tmp/neuroforge-models.tar
```

**5. Проверить** — вкладка Models должна показывать модели скачанными, без кнопки Download.

Если что-то пошло не так, `neuroforge-models.tar` всё ещё на компьютере: можно повторить
шаг 4.

## Если компьютера нет

Тогда этот переход придётся сделать с потерей: удалить, поставить 1.4.1, скачать модели
заново. Дальше обновления уже будут вставать поверх, и повторять это не понадобится.

## Почему модели не лежат где-нибудь, откуда их не сотрёт удаление

Потому что нативным рантаймам нужен **настоящий путь в файловой системе**. LiteRT-LM
получает путь и отдаёт его в нативный код, llama.cpp открывает файл через `fopen`. Storage
Access Framework, который переживает удаление приложения, выдаёт `content://`, а не путь —
чтобы им воспользоваться, файл пришлось бы копировать обратно во внутреннее хранилище, то
есть держать две копии гигабайтных весов. `Android/data` удаление тоже стирает, и с
Android 11 он ещё и не виден файловым менеджерам.

Поэтому решение здесь — не переносить модели, а не удалять приложение. Постоянная подпись
это и обеспечивает.
