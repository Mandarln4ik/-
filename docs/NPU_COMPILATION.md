# Компиляция моделей под NPU (AOT)

Это тот самый конвертер, который я обещал. Он превращает `.tflite` в граф, который APU
запускает **без предварительной компиляции**.

Без него вендорный рантайм либо компилирует граф на устройстве при первой загрузке — это те
самые десятки секунд, — либо не справляется, и модель тихо уезжает на CPU. Для `.litertlm`
у этого шага есть узнаваемый след: сборка без AOT-нагрузки падает с `TF_LITE_AUX`, и
приложение показывает это сообщение словами, а не кодом.

```bash
pip install ai-edge-litert ai-edge-litert-sdk-mediatek
python3 tools/npu/compile_for_npu.py model.tflite --soc MT6991 --out ./npu
```

`--soc` берётся с телефона: вкладка **Device** показывает `Build.SOC_MODEL`. На вашем
аппарате это `MT6991`.

## Где это может работать, а где нет

**Только x86_64 Linux.** Это не предположение — проверено распаковкой обоих колёс:

| файл | x86_64 | aarch64 |
|---|---|---|
| `vendors/mediatek/compiler/libLiteRtCompilerPlugin_MediaTek.so` | **есть** | **нет** |

То есть **на самом телефоне это не запустится**, сколько бы остального тулчейна ни вставало
в Termux: именно тот кусок, который компилирует, под ARM не собран. Нужен десктоп, CI-раннер
или Colab — а результат копируется на телефон файлом.

`ai-edge-litert-sdk-mediatek` даёт `libneuron_adapter.so` из MediaTek NeuroPilot SDK. Без
него плагин загрузится, опознает чип (`SoC model mt6991 is supported`) и упадёт на
`Failed to load NeuronAdapter shared library` — выглядит как сломанная установка, хотя это
просто недостающий пакет.

## Компилируется не всё

Компиляция идёт **по операторам**: плагин разбивает граф и забирает то, что умеет. Если он
не берёт ничего — это ответ про модель, а не ошибка, которую надо обойти.

Замерено здесь, цель MT6991:

| модель | результат |
|---|---|
| `selfie_multiclass_256x256.tflite` | **скомпилировалась**, 2,5 с, 8,6 МБ |
| `esrgan_int8.tflite` (апскейлер) | **отклонена**, 0 операторов из 910 |

У ESRGAN причина конкретная: слои `PReLU` — `output type is incompatible with inputs` по
мнению компилятора MediaTek. Поэтому апскейлер в приложении идёт через JIT-путь NPU, а не
через AOT.

Скрипт печатает результат разбиения, а не просто «успех/ошибка»: вопрос, который стоит
задавать, — «сколько операторов он взял».

## Что это меняет для приложения

Для `litert-community` это уже сделано за нас — там лежат сборки `..._mt6991.litertlm`,
скомпилированные ровно этим путём, и приложение выбирает их автоматически по
`Build.SOC_MODEL`. Свой скрипт нужен, когда модели под ваш чип никто не выложил.
