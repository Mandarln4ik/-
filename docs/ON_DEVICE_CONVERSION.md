# Конвертация моделей на самом телефоне

**Да, это возможно.** Раньше я утверждал обратное — утверждение было неверным, и вот в чём
именно я ошибся.

## Что я говорил и где ошибся

Я говорил: «конвертация PyTorch → LiteRT на Android невозможна». Верно было только для
**внутри APK**: Android-приложение это песочница JVM, в ней негде держать Python и
MLIR-компилятор.

Но телефон — это не только приложение. Termux даёт полноценный Linux-userland на тех же
ARM64-ядрах, и весь тулчейн под ARM64 существует. Проверено скачиванием пакетов, а не
рассуждением:

| Пакет | Сборка под ARM64 |
|---|---|
| `torch` 2.14 | `manylinux_2_28_aarch64` |
| `tensorflow` 2.21 | `manylinux_2_27_aarch64` |
| `ai-edge-litert` 2.2 | `manylinux_2_27_aarch64` |
| `ai-edge-torch` 0.7.2 | чистый Python |
| `ai-edge-quantizer` 0.9 | чистый Python |

Никакой эмуляции: ядра телефона исполняют конвертер нативно.

## Чего делать НЕ нужно

**Не пытайтесь поднять подсистему Windows.** WSL — компонент ядра Windows, на Android его
нет. А x86-эмуляция на ARM (QEMU, Box64) работает, но замедляет в 10–50 раз — конвертация,
которая на десктопе занимает минуты, растянется на сутки. Смысла нет: нативные ARM-сборки
уже существуют, эмулировать нечего.

## Установка

Termux — **только с F-Droid или GitHub**. Сборка из Google Play заброшена и не ставит пакеты.

```bash
# в Termux
curl -sL https://raw.githubusercontent.com/Mandarln4ik/-/main/tools/android/setup.sh -o setup.sh
bash setup.sh
```

Скрипт ставит `proot-distro`, разворачивает Debian aarch64 и собирает в нём venv с
тулчейном. Занимает несколько гигабайт и заметное время.

## Конвертация

```bash
proot-distro login debian -- bash -c '
  . /root/neuroforge-venv/bin/activate
  python3 /root/convert.py \
    --entry my_pkg.models:build_model \
    --shape 1,3,256,256 \
    --quantize full_int8 \
    --calib /root/calib \
    --out /root/model_int8.tflite
'
```

Готовый файл кладётся в каталог моделей приложения:

```
/sdcard/Android/data/dev.neuroforge/files/models/<id-модели>/
```

## Два правила, которые нельзя нарушать

**Форма входа обязана быть статической.** NPU компилирует одну форму и повторяет её.
Динамическая ось означает перекомпиляцию на каждый вызов либо отказ. Скрипт требует
`--shape` и отвергает нули.

**Калибровка должна быть похожа на реальный вход.** Полноцелочисленная квантизация
записывает диапазоны активаций, прогоняя модель по образцам. Дайте ей шум — диапазоны
уедут, и это проявится полосами и швами на картинке, а не ошибкой.

## Пределы, о которых стоит знать заранее

**Память.** Конвертация держит модель и её промежуточное представление одновременно. На
12 ГБ модель 0.6B пройдёт с запасом; 4B — почти наверняка нет. Скрипт печатает доступную
память и предупреждает ниже 6 ГБ.

**Время.** Ядра телефона медленнее десктопных и троттлят под нагрузкой. Считайте часы, а не
минуты, и держите телефон на зарядке.

**Место.** Тулчейн — несколько гигабайт, плюс исходная модель, плюс результат.

## Чего я не проверял

Доступность ARM64-пакетов я проверил: скачал `ai_edge_litert-2.2.0-cp311-cp311-manylinux_2_27_aarch64.whl`
и остальные. **Полный прогон конвертации на телефоне я не выполнял** — у меня нет
ARM64-устройства и нет доступа к Hugging Face из среды сборки.

То есть: путь обоснован проверенными фактами, но не подтверждён успешным запуском. Если
он упрётся — вероятнее всего в память или во время, а не в архитектуру. Пришлите вывод, и
я разберу конкретную ошибку.

## Альтернатива, если телефон не потянет

В репозитории есть workflow, который делает то же самое на сборочной машине GitHub и
кладёт результат в релиз. Вы так же не трогаете ПК — просто работу делает не телефон.
